# Redis Distributed Locks Subsystem (Shared/Exclusive)

Продвинутая подсистема блокировок для Laravel 12, реализующая паттерн **Reader-Writer Lock**. Позволяет синхронизировать тяжелые процессы записи (синхронизацию кэша) и распределенное чтение без риска «грязных» данных или Race Conditions.

## Состав системы

1. **`LockManager`** — точка входа (фабрика). Создает экземпляры блокировок.
2. **`RedisExtendedLock` (Exclusive)** — эксклюзивная блокировка («писатель»). Использует Lua-скрипты для атомарного продления и удаления только владельцем.
3. **`RedisReadLock` (Shared)** — разделяемая блокировка («читатель»). Работает на базе атомарного счетчика в Redis.
4. **`ResourceLockedException`** — исключение, выбрасываемое при попытке доступа к занятому ресурсу.

------

## Основные концепции

## Эксклюзивная блокировка (Write Lock)

Гарантирует, что только один процесс выполняет операцию.

- **Owner-based:** Каждый лок имеет уникальный токен. Процесс не может случайно удалить или продлить «чужой» лок, если его собственный истек.
- **Heartbeat:** Поддержка метода `extendOrFail()`, чтобы продлевать блокировку в процессе выполнения долгой задачи.

## Блокировка чтения (Read Lock)

Позволяет множеству процессов читать данные одновременно.

- **Барьер для записи:** «Писатель» не начнет подмену данных, пока счетчик активных читателей не станет равен 0.
- **Ожидание записи:** Читатели могут ждать (метод `waitForRelease`), пока «писатель» закончит обновление.

## Примеры использования

### 1. Синхронизация данных (Писатель)

Используется для перестроения тяжелых кэшей. Сначала заполняем временный ключ, затем ждем ухода читателей и атомарно подменяем данные.

```php
// 1. Пытаемся захватить эксклюзивный доступ
if (!$lockManager->writeLock->get()) {
    throw new ResourceLockedException('Sync already in progress');
}

try {
    // 2. Ждем, пока текущие читатели закончат работу (max 60 сек)
    $lockManager->readLock->wait(
        timeout: 60,
        // В процессе ожидания продлеваем свою блокировку записи
        onWait: fn() => $lockManager->writeLock->extendOrFail()
    );

    // --- СЕЙЧАС НОВЫЕ ЧИТАТЕЛИ НЕ МОГУТ ВОЙТИ ---

    // 3. Наполняем временный кэш (Shadow Cache)
    fillTempCache(callback: fn() => $lockManager->writeLock->extendOrFail());

    // 4. Атомарная подмена ключей в Redis
    Redis::rename('cache_temp', 'cache_main');

} finally {
    $lockManager->writeLock->release();
}
```

### 2. Потоковое чтение (Читатель)

Используется в API для безопасной отдачи данных через `StreamedResponse`.

```php
return response()->stream(function() use ($lockManager) {
    // 1. Ждем, если в данный момент идет синхронизация (висит write lock)
    $lockManager->writeLock->waitForRelease(60);

    // 2. Регистрируем себя как читателя (+1 к счетчику)
    $lockManager->readLock->acquire();

    try {
        // 3. Стримим данные (например, через hscan)
        streamMyData();
    } finally {
        // 4. Обязательно освобождаем лок (-1), даже если клиент оборвал связь
        $lockManager->readLock->release();
    }
});
```

## Установка и настройка

1. Перенесите классы в директорию `App\Support\Locks`.
2. Зарегистрируйте `LockManager` в `AppServiceProvider` как синглтон.
3. Убедитесь, что в `config/database.php` настроено подключение Redis.

## Особенности реализации

- **Атомарность:** Все проверки счетчиков и владельцев выполнены через **Lua-скрипты**.
- **Безопасность:** Исключены ситуации, когда один процесс удаляет блокировку, установленную другим процессом после таймаута первого.
